# Licences shipped with Videobeaux

| File | What |
|---|---|
| `VIDEOBEAUX-LICENSE.txt` | The licence of Videobeaux itself — **placeholder: choose one before distributing**. |
| `FFMPEG-LICENSES.txt` | Generated by `tools/ffmpeg-build/` for the bundled ffmpeg: version, configure line, every linked library and its licence. |
| `THIRD_PARTY_NOTICES.txt` | Python packages, models and other dependencies (generate with `audit_licenses.py`). |

## The bundled ffmpeg

* Built by this project from source (`tools/ffmpeg-build/`), configured `--enable-gpl` (for libx264 and libx265) and
  **never** `--enable-nonfree`. The build script and CI both refuse a nonfree result, and so does the installer build
  and the app's own check (`gui/src/main/toolsSetup.js`).
* It is a separate program that Videobeaux starts as a child process; Videobeaux does not link against it.
* Corresponding source: every release of the build publishes the exact source archives next to the binaries
  (`sources-*.tar`, with SHA-256 in `SOURCES.txt`). Keep those archives available for as long as you distribute the
  binaries (the GPL requires the offer to remain valid).
* You can point Videobeaux at your own ffmpeg instead (Setup → ffmpeg path), for example an LGPL build.

## Before charging for the app (checklist)

1. Publish the ffmpeg release (`ffmpeg-7.1.1-vb2`), paste `ffmpeg-runtime.sha256.json` into `gui/ffmpeg-runtime.json`, and delete
   the `devFallback` block (it points at a *nonfree* third-party build that is only tolerated for local development).
2. Keep that release's `sources-*.tar` online for as long as you distribute the binaries.
3. Decide Videobeaux's own licence (`VIDEOBEAUX-LICENSE.txt` is a placeholder) and ship `FFMPEG-LICENSES.txt` and
   `THIRD_PARTY_NOTICES.txt` inside the installer.
4. Code-sign: macOS needs a Developer ID certificate, the hardened runtime (including the bundled `ffmpeg`/`ffprobe`) and
   notarisation; Windows needs a code-signing certificate. The bundled ffmpeg is only ad-hoc signed today.
5. Legal review: GPL "separate program" position, H.264/HEVC/AAC patent licensing, x264/x265 commercial licences if you
   want to avoid the GPL route, and the licences of the AI models (some are non-commercial).

> This is an engineering summary, not legal advice. Have the distribution model reviewed before charging for the app —
> in particular the "separate program" position, H.264/HEVC patent licensing, and the licences of the bundled models.

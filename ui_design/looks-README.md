# Looks — trying a visual identity without committing to it

Videobeaux can wear different **Looks**. Pick one in **🎨 Appearance → Look**:

| Look | What it adds (on top of the original UI) |
|---|---|
| **Classic** | Nothing. The original Videobeaux Television UI, byte for byte. Always available. |
| **Patterns** | The first attempt: one Memphis tile per *family* (12 tiles shared by many modules). Kept for comparison. |
| **Motifs** | Header patterns **with a reason**: each module's pattern depicts what it does (rolling scan-bands for VHS, nested frames for Feedback, a snowflake for Freeze…), one pattern per mechanic, never shared across categories. The full table is `ui_design/pattern-map.md`; the drawn version is `ui_design/pattern-gallery.html`. |
| **Signatures** | Motifs + a cartoon glyph chip in each header, a recognisable strip with the glyph and a one-line description when a module is **collapsed**, and *By category / By family* grouping in the sidebar. |
| **Output art** | Signatures, but the collapsed-module picture and a **hover preview** in the sidebar are cropped from what each module *really produces* — from the built-in clip or **your own video** (Appearance → Module previews → Choose clip…, or drop a clip in `ui_design/art_source/`). |

In every non-Classic look the grey system tooltips are replaced by Videobeaux-styled ones, and the sidebar shows a hover card
(picture when there is one, description always).

Everything else you asked for is **not** a Look and works in all of them: collapse/expand on every module (double-click
a header, or Controls → ▤ / ▦ for all), a setting on every module, line colour (*Lines*), and a canvas background image
with opacity (*Canvas background*).

## Going back
* **Instantly:** Appearance → Look → Classic.
* **Remove a look for good:** delete its folder in `gui/src/renderer/src/looks/` and its line in `looks/index.js`
  (anyone who had it selected falls back to Classic).
* **Whole-source rollback:** `tools/ui-snapshot.sh list` → `tools/ui-snapshot.sh restore <name>`
  (it saves the current state as `before-restore` first). Snapshots live in `ui_design/_snapshots/`.

## How it is built
* `looks/registry.js` — **program id → family**. Visual only; presets and processing never see it. Edit `OVERRIDES` to move a
  module to another family.
* `looks/motif-data.js`, `looks/shared/motifs.css`, `ui_design/pattern-map.md`, `ui_design/pattern-gallery.html` — all generated
  by `python tools/gen_motifs.py`. **The module → motif table lives in that script** (one entry per motif: category, label,
  reason, modules, drawing). A unit test fails if a motif is shared across categories or a module has none.
* `looks/shared/patterns.css` — the first attempt's family tiles, generated by `tools/gen_look_patterns.py`.
* `looks/<look>/look.css` — rules scoped under `:root[data-look="<look>"]`. A unit test fails if one is not scoped.
* `looks/signatures/glyphs.js` — family glyphs + hand-drawn glyphs for ~35 flagship modules (`PROGRAM_GLYPHS`).
  Add one: drop an entry keyed by program id.
* `looks/output-art/art/*.webp` + `manifest.json` — made by `python tools/make_module_art.py` (runs every module on one clip
  through the smoke-test runner, keeps the most interesting frame). `--source my.mp4 [--start 5 --duration 4]` uses your
  footage, otherwise `ui_design/art_source/*` is used, otherwise a generated clip. `--only id1,id2` refreshes a few.
  Modules that can't run (faces/speech/network without a suitable clip) fall back to the glyph. In the app, the user's own
  set is rendered into the user-data folder and replaces the bundled one entirely ("Use built-in" brings it back).
* `components/BrandedTooltips.jsx` — the tooltip layer (moves `title` into `data-tip`; `data-no-tip` opts an element out).

## Reference material
`ui_design/` holds the mock-ups and the pattern sprite sheet that inspired this. They are **reference only**: the
sprite sheet is labelled as ripped from a game, which is almost certainly someone else's artwork, and Videobeaux is meant to
be sold. Everything shipped in the app is original (drawn in `tools/gen_look_patterns.py` and `glyphs.js`).

## Adding a new Look
1. `looks/mylook/look.css` with selectors starting `:root[data-look="mylook"]`.
2. `import './mylook/look.css'` and an entry in `looks/index.js`.
3. Hooks you can style: `.node-header[data-family]`, `.node-glyph`, `.node-art`, `.node-art-thumb`, `[data-collapsed="true"]`,
   `.cat-chip[data-family]`, `.prog-dot[data-family]`, and the CSS variable `--node-color` (the module's category colour)
   and `--pat` (its family pattern).
